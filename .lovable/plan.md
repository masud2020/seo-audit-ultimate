# Phase 4 build plan

Four features, delivered in one pass. Skipping live SERP tracking this turn — DataForSEO onboarding needs its own step (API key + endpoint mapping) and would double the surface area.

## 1. Whole-site audit view (crawler aggregate)

The crawler already collects per-page data + per-page issues. Add a **site-level roll-up** on `/crawler/$id`:

- **Site health score** (0–100) derived from issue severity and page count.
- **Issue-type aggregation**: group identical `message` prefixes → count + affected URLs.
- **Averages panel**: avg words, avg load ms, avg page KB, % pages with title/description/H1, noindex pages, 4xx/5xx totals.
- **Top offenders**: 5 slowest pages, 5 largest pages, 5 lowest word-count pages.
- **Export**: JSON export of the whole crawl.

No new tables. Purely a UI + light server aggregation on the existing `site_crawls` row.

## 2. Gap analyses (keyword / content / backlink)

New route `/gaps` using the user's stored Semrush API key (already in `api_settings.semrush_key`).

Server functions in a new `src/lib/gaps.functions.ts`:

- `keywordGap({ your_domain, competitor_domain, database })` → Semrush `type=domain_domains` intersection, returns keywords the competitor ranks for that you don't (position, volume, CPC, difficulty).
- `contentGap({ your_domain, competitor_domain })` → Semrush `type=url_organic` for the competitor's top pages (`type=domain_organic_pages`) not present on your domain — surfaces topics/URLs to cover.
- `backlinkGap({ your_domain, competitor_domain })` → Semrush `type=backlinks_competitors` + `backlinks_refdomains` to surface referring domains linking to competitor but not you.

UI: two-domain picker (your domain + competitor), three tabs (Keywords / Content / Backlinks), sortable tables, CSV export per tab.

## 3. Toxic backlinks + disavow export

New route `/disavow` using Semrush `type=backlinks` for the user's domain.

- Pull up to 500 backlinks with `source_url,source_title,anchor,external_num,internal_num,domain_ascore,page_ascore,nofollow,first_seen,last_seen`.
- Toxicity score = weighted signal: low `domain_ascore` (<15), spammy anchor patterns (drugs/casino/adult keyword list), excessive `external_num` on source page, sitewide footprint. Bucket into **Toxic / Suspicious / Healthy**.
- User can toggle individual rows or bulk-select buckets → **Export disavow.txt** in Google's format:

```text
# Generated by SEO Audit Tool on {date}
# Domain: {your_domain}
domain:spamdomain1.com
domain:spamdomain2.com
https://spam.example.com/specific-page
```

- Persist selections in a new table `disavow_entries (id, user_id, domain, target_domain, source_url, reason, created_at)` so exports are reproducible.

## 4. PDF export + email delivery

Server-generated PDF using `pdf-lib` (Worker-safe, pure JS). Replaces the current client `window.print()` on the audit page and reuses it from the crawler summary.

- `generateAuditPdf({ audit_id })` server function → assembles the audit report + AI recs into a branded PDF, returns base64 for download.
- `emailAuditPdf({ audit_id, to })` server function → renders the same PDF, sends via the **Brevo** connector (`smtp/email`, base64 attachment) using the standard connector gateway. Reason for Brevo over Lovable Emails: attachments aren't supported by Lovable Emails; Brevo supports them natively with one HTTP call, no email-domain setup required beyond a verified sender.
- UI: on `/audit/$id`, keep "Export PDF" (now server-side, downloads .pdf) and add "Email PDF" dialog (recipient + optional note). Same buttons added to `/crawler/$id`.

Prerequisites we'll surface in the UI:

- Brevo connector must be linked (I'll trigger the connect flow if not present).
- User provides a verified sender email in Settings (new field `sender_email` on `api_settings`).
